# Audit Report

## Unreleased root migration audit

- Exact client process matching prevents `CamfrogStatusChanger.exe` and similarly named helper applications from making the dashboard report Camfrog as running.
- Automation refuses ambiguous Camfrog windows and status controls. Generic UIA ComboBoxes without an exact configured automation ID, native Camfrog class, or observed status value are rejected before any fallback write.
- Fresh config defaults and registry test fixtures no longer contain account-specific status strings or contact data.
- Pillow was updated after the dependency audit reported vulnerabilities in the prior pinned version.
- The Inspect worker's exception callback now captures the error before leaving the `except` scope.
- The dashboard stays visible when the tray cannot be started, restores itself if the tray thread later stops, and exits cleanly on close instead of hiding without a working tray icon.
- The Ubuntu baseline workflow runs the complete pytest suite with application dependencies installed.
- Historical release ZIPs in the former app subtree contain account-specific identity/contact strings in bundled source and bytecode fixtures. They were not copied into root `tags/`; the original Git history is unchanged by this worktree cleanup.
- The Windows workflow builds the x64 executable and uploads the executable and manifest as a temporary workflow artifact; they are not stored in the Git checkout. The executable was not launched against Camfrog, so live UI, status, room, and server behavior remain unverified.

## Fixed defects captured during development

- P2 startup/config audit: guarded startup initialization and UI imports, made language selection tolerate wrong-shaped UI config, added a temporary Tk messagebox root with guaranteed teardown, and added pre-logging `app.log` fallback from APPDATA to `%TEMP%`. Single-instance acquisition now fails closed if mutex creation fails and closes duplicate handles; Windows releases a process's handles on termination, so no manual stale-lock stealing was added. Atomic config replacement retries transient permission failures four times and preserves the previous config on exhaustion. Valid JSON with wrong-shaped `ui` data was already backed up and recovered by `ConfigStore`; regression tests now cover `null`, list, string, and integer shapes. No schema migration was required. No multiprocessing or spawn use was found. Local checks passed: 250 pytest tests, `compileall`, `scripts/validate_repo.py`, and `git diff --check`; Windows CI and live Camfrog behavior were not run.
- P3 moderation audit: confirmed the history reader split embedded newlines into independent message lines, allowing a continuation such as `Victim: badword` to be attributed to a forged sender. Moderation now uses explicit visible UIA child-row boundaries and pauses when a row contains embedded newlines or no child-row structure is available; Auto reply and room-event parsing were left unchanged. Confirmed Thai substring false positives (`สลัด` in `สลัดผัก`) and a quadratic adversarial regex scan exceeding the new 0.5-second test budget before the fix; matching now masks the allowlist first, applies Unicode token boundaries, and wraps obfuscation patterns with boundaries. Confirmed nickname `.strip()` accepted leading/trailing whitespace and a terminal newline, templates accepted Unicode line/control separators, and `None` was coerced to the literal target `None`; these are now rejected. Config validation no longer trims unsafe nickname whitespace into a sendable value. Leading/internal slash, direction/zero-width format characters, and over-64-character names were already rejected; corpus tests preserve those guards. Exact-command confirmation was already present in `send_action` and the dashboard, and remains covered by existing tests. Cooldown is now per sender within the configured room. Auto kick has a five-submission rolling 60-second cap; the next attempt logs and persistently disables its setting. Room actions and Auto kick defaults remain disabled; no schema migration was needed. Regression tests were written first and failed against the previous behavior. Local checks passed: 259 pytest tests, `compileall`, `scripts/validate_repo.py`, and `git diff --check`; all Windows/UIA interactions were faked and no live room action was sent.
- P4 send-path audit: confirmed the UIA sender dispatched Enter after a fixed 450 ms delay without checking the foreground process or rereading the Edit, while Win32 send routes likewise did not recheck the target text at dispatch. The app had no per-monitor-v2 initialization, although both foreground and background compatibility fallbacks calculate screen coordinates. Confirmed `RotationWorker` passed naive `datetime.now()` to the local schedule and that `set_status()` returned immediately when another Apply held its nonblocking lock. Regression tests failed on these paths before the fix. Foreground sends now poll for the selected Camfrog PID, verify the target Edit handle and exact status text, and recheck directly before Enter; mismatch aborts without sending. If UIA cannot uniquely identify the status Edit, the foreground route skips all keyboard input and Enter, while the guarded background route may try only after finding an Edit. Win32 paths use a bounded exact-text poll before their single Enter. Startup configures or confirms per-monitor-v2 before dashboard/Tk initialization; coordinate routes fail closed without confirmation and require a uniquely identified Edit. Manual and rotation requests serialize through the controller lock, and the monotonic minimum-interval gate is covered by an eight-request concurrent fake-clock test. Rotation supplies an aware local datetime and waits against monotonic deadlines. DST spring-forward/fall-back wall-time behavior and overnight midnight boundaries are covered. The history-source and single-character marquee settings use an explicit schema 3 migration, including schema 1 legacy message rows. Local checks at the initial P4 completion passed: 275 pytest tests, `compileall`, `scripts/validate_repo.py`, and `git diff --check`; the pre-push follow-up regression test failed before its guard fix. Latest full local validation passes 298 pytest tests, `compileall`, `scripts/validate_repo.py`, `pip-audit`, and `git diff --check`; exact-head CI and live Camfrog status acceptance remain unverified.
- P4 reviewer follow-up: regression tests reproduced a missing `win32con` import on the combo-notification path, clipboard loss when coordinate fallback verification aborts, and a stopped rotation proceeding after it waited on the status lock. The import is local to the Windows call path, coordinate fallback restores clipboard state from `finally`, and rotation cancellation is checked while waiting for the lock and before dispatch. The callback still supports existing one-argument consumers. A fourth test caught and fixed cancellation results mislabeling the requested text as the previous value. All 302 local tests, `compileall`, `scripts/validate_repo.py`, and `pip-audit` pass. No live Camfrog/UIA action was performed; exact-head GitHub checks and the Windows build remain pending.
- P5 registry audit: confirmed `registry_history_dump.py` wrote without creating its parent directory, let registry/storage exceptions escape, and returned success for an empty scan. Confirmed the reader filtered sensitive value names but still traversed `Session` and credential key branches, while binary carving accepted unterminated truncated fragments and odd-offset decoding could emit corrupted text. Regression tests failed before changes. The dump now creates its directory, reports scan/storage/write failures with nonzero status, and rejects `scanned_keys == 0`; `--redact` optionally masks email, phone-like, and URL strings while default output remains unchanged. Sensitive branches are skipped before traversal, `winreg` remains Windows-only at call time, and binary carving accepts only delimiter-terminated runs. Fake Registry tests and neutral fixture files cover Linux import, scope filtering, metadata prefixes, odd alignment, and truncated UTF-16LE/ASCII data. Dumps still contain user-authored status text and source metadata by default and must not be shared. No config schema or dependency changed. Local checks passed: 286 pytest tests, `compileall`, `scripts/validate_repo.py`, and `git diff --check`; no Windows Registry or live Camfrog read was performed.
- P1 status-style audit: replaced executable Python format-string handling with strict `{text}` / optional `{color}` validation and a plain-text fallback; added a localized invalid-template preview message. Marquee frames retain Unicode combining/emoji sequences, skip blank frames for nonblank statuses, and use a validated palette plus bounded width coercion. The legacy two-line helper now preserves all supplied rows, and comparison removes NULs and applies NFC. Ubuntu-local validation passed 224 pytest tests, `compileall`, and `scripts/validate_repo.py`; Windows CI and live Camfrog behavior were not run.

- Manual room actions are configurable visible-UI commands with a confirmation on every send. ## Remaining high-risk uncertainty

The exact Camfrog internal commit/publish path is not yet runtime-verified end to end. Static analysis identifies `Messages::ChangeStatus`, `SetSelfStatus`, and `CSPacket020401.text_status`, but the application deliberately does not invoke unverified internal RVAs.

Room-command syntax, account role, Camfrog server authorization, and kick results have not been validated in a live room. Templates are empty by default, and no moderation action should be described as server-confirmed based on UIA submission alone.
